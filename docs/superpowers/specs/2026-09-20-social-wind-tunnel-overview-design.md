## 1. 目标与非目标

**一句话**：用 TypeSafe 的 Jev（System One 模型：文本状态进，带校准概率的类型化决策出；不生成文本）作为"行为转移核"，构建可大规模、可重复运行的虚拟人群模拟；用公开的人类数据逐层验证；以"消息风洞" demo 和一项可量化的应用分析展示应用潜力。

**交付物**

1. 论文一篇，主张 C1–C4（§2）。
2. 可演示的 demo「消息风洞」：回放模式（无需 API key，可随论文分发）+ 实时模式。
3. 可复现包：代码 + 固定模型版本号 + **聚合结果与输入哈希**。Jev 是闭源且版本会移动的模型，需要让他人无需访问权限即可核对论文里的数字。
   **注意（2026-09-20 核实条款后修订）**：原计划发布完整响应缓存。TypeSafe 的 MCA §4.2 把 Output 的所有权转让给客户，但 §2.3(b) 禁止用 Output 做蒸馏或"协助开发"类似产品，且无学术例外。十几万条「问题 → 概率分布」的缓存功能上即蒸馏数据集，因此默认**只发布聚合结果、代码和输入哈希**；如需发布完整缓存，先取得 TypeSafe 书面许可。详见 `docs/jev-research.md` §13。

**非目标（明确不做）**

- agent 自由生成文本（发帖、对话）。"发帖"一律是从真实内容池中选择；LLM 生成不在核心范围内。
- 核心实验里的非美国人群。验证数据集中在美国 / 英语；日本、中国只作为扩展小节（E7）。
- 预测真实选举、把模拟结果当作真实民调发布。
- "帮我优化这条消息的说服力"一类功能。demo 只比较用户给定的方案，不做说服力搜索。
- 微调任何模型、本地部署开源权重基线（开源微调模型的数字引用已发表结果）。
- 多用户在线托管服务。

## 2. 论文主张、证据与放行门槛

| 主张 | 内容 | 主要证据 | 子项目 |
|---|---|---|---|
| **C1 核的保真度** | Jev 给出的选择分布是对人类回答的忠实、校准的预测；成本低两个数量级 | OpinionQA（人群级分布）；SocSci210 未见研究（个体级、带实验条件）；对比 LLM 基线与已发表数字；温度重校准；成本-保真度 Pareto 图 | SP1 |
| **C2 个体自洽与可控** | 并行问题互相隔离会使个体"不自洽"；分层潜在特质能恢复题间相关结构；施加的特质可从回答中恢复 | 题间相关矩阵恢复；剂量-反应排序 | SP2 |
| **C3 便宜买到的是统计功效** | 经微观验证的核组合成传播模拟后，能以数百次重复给出带置信区间的干预排序；只跑 k≈3 次（常见做法）时排序不可靠 | Pennycook et al. 2021 个体数据上的微观验证（含 accuracy prompt 的真实干预效应）；每组 ≥200 次重复 + common random numbers；"k 次运行的排序一致概率"分析；成本账本 | SP2、SP3 |
| **C4 应用价值可量化** | (a) 干预风洞：带不确定性的方案排序；(b) 混合真人 / 硅基抽样：一次 Jev 预测"值多少个真人样本"（有效样本量 κ*），同等误差下节省多少真人样本 | demo；OpinionQA / SocSci210 上的离线预算分配实验 | SP4、SP5 |

**放行门槛（事先写定，避免事后合理化）**

- **G1（SP1 结束时）—— 核是否可信。** 基准是 SocSci210 未见研究上的分布距离（越低越好；已发表参照：均匀猜测 0.203，GPT-4o 0.174，微调的 Socrates-Qwen-14B 0.151，经验下界 0.125）。
  - 强通过：Jev 零样本 ≤ 0.174（不差于 GPT-4o）。
  - 通过：重校准后 ≤ 0.185，且明显优于均匀猜测，同时单位成本 ≤ 旗舰 LLM 基线的 1/50。
  - 不通过：重校准后仍不优于均匀猜测 → 停止 SP2 之后的工作，论文退回"评估型论文"（只做 C1，如实报告负面结果与重校准分析）。
  - "条件不敏感的合并人类分布"基线**不是**要打败的对象：它用的是同一研究的真实答案，是 oracle（两个真实分片上实测 0.041，均匀 0.144）。它用作标尺：报告"从均匀到 oracle 的差距里模型补上了多少"。
  - 我们只评估量表可解析的任务（超过 101 级的金额类任务除外），与论文的全集有出入，须如实说明。
  - 前提：必须先通过"指标对齐检查"（SP1 §6.3），确认我们算的分布距离与原论文可比；否则 G1 改用我们自己在同一子样本上重跑的 LLM 基线作参照。
- **G1b（与 G1 同时判定）—— 核是否对处境敏感。** 2026-09-20 预注册，在用冻结问法跑任何测试集之前写定。
  - **为什么需要这条。** G1 用的分布距离奖励"把整体水平估对"。实测发现，一个把同一研究内各实验条件**合并**后的真人分布（"合并人类分布"基线）在该指标上得 0.041，远好于论文里 GPT-4o 的 0.174——但它对实验条件的区分能力恰好是 **0**。也就是说，**G1 的指标可以被一个对模拟毫无用处的预测器刷到接近满分**。模拟需要的恰恰是"处境变了，行为随之变"，所以必须单独立一条判据。
  - **怎么算。** 在 SocSci210 测试研究上，对每个 `(研究, 结果变量)`，取各实验条件下的预测均值与真人均值（回答缩放到 [0,1]），**在任务内各自中心化**以消去任务整体水平，汇总后算 Pearson r；同时报告回归斜率（预测移动一单位对应真人移动多少）与 bootstrap 置信区间。
  - **通过**：r ≥ 0.25 且 bootstrap 95% 置信区间下界 > 0。
  - **不通过**：r 与 0 无法区分 → 该核无法驱动"对干预有反应"的模拟。此时即使 G1 通过，C3 / C4 也不成立，论文退回评估型，并把"聚合指标可被条件盲基线刷分"作为方法学发现写出来。
  - **阈值依据**：开发集实测 p3 为 0.546、p1 为 0.346（27 个研究、1371 次预测）。测试集预期会下降，0.25 是保守下限。阈值只依据开发集数据设定，测试集在冻结后只跑一次。
  - 两个条件盲基线（均匀、合并人类分布）在此判据上恒为 0，是地板参照。
  - **勘误二（2026-09-20，冻结之后、跑测试集之前补记）：阈值 0.25 与"置信区间下界 > 0"这两句都偏弱。** 预注册时我把两个不同的问题混为一谈：bootstrap 区间回答"r 估得多准"，而 G1b 真正要问的是"r 是否区别于偶然"。后者需要**置换检验**——在每个任务内打乱预测与条件的配对、保留全部边际分布，得到"预测不含条件信息"时 r 的分布。实测该空分布很宽：开发集上 95 分位达到 **0.275**，**高于预注册的 0.25**；一个只对 state 做哈希、毫无真实敏感度的 mock 核也能拿到 r = 0.131、bootstrap 下界 0.004（> 0）。也就是说照字面执行，空模型可以通过后半句判据。
    **处置（不改上方冻结文字，在此声明更强判据，且在跑测试集之前）**：以置换检验为准——`permutation_p < 0.01` **且** `r > null_p95`。两个统计量已实现在 `metrics.condition_sensitivity` 中，随每次运行写入 `metrics.json`。开发集上 p3 为 r = 0.640、null p95 = 0.275、p = 0.0005，同时满足新旧两套判据，所以这条勘误不改变对 p3 的判断；它改变的是"一个刚过 0.25 的结果该怎么读"——那样的结果**不应**被判为通过。

  - **勘误（2026-09-20，实现之后补记，不修改上方已冻结的预注册文字）**：实现中这两个基线返回的是 `None` 而非 `0`——它们的跨条件预测变动恒为零，相关系数在数学上无定义。判读不变：地板是"与 0 无法区分"。作为对照，mock 核（无真实条件敏感度）实测 r = 0.0076，bootstrap 95% 区间 [−0.062, 0.070]，正确地落在地板上。

- **G2（SP2 结束时）—— 场景是否站得住。** 在 Pennycook 数据的留出研究上：(a) 标题级平均转发意愿的预测-实测相关 r ≥ 0.5；(b) accuracy prompt 对"转发辨别力"（真新闻 − 假新闻）的效应方向正确；(c) 分层潜在特质相对独立采样改善了题间相关恢复。若 (b) 不通过，SP3 的干预实验降级为"探索性"，论文的 C3 只保留重复运行的方法论结论。

## 3. 系统总览

```
                ┌──────────────── demo（SP4）────────────────┐
                │  FastAPI 后端  ←→  前端（回放 / 实时）       │
                └───────────────────▲────────────────────────┘
   eval（SP1 / SP2 / SP5）          │        engine + scenario（SP3）
   OpinionQA · SocSci210 ·          │        tick 循环 · CRN 采样 ·
   Pennycook · 混合抽样             │        转移核制表 · 事件日志
          └────────────────┬────────┴───────────────┘
                           ▼
          population：Persona · 原型（带权重）· 潜在特质
                           ▼
   kernel 层：Kernel 协议 → Jev │ Adapter(LLM) │ Table │ Mock
              包装器：缓存 · 限流 · 预算 · 账本
```

**分层原则**：上层只依赖 `Kernel` 协议，不知道背后是 Jev、LLM 适配器、查表还是 mock。这让 (1) 没有 Jev 访问权限时也能开发和测试，(2) 基线对比只是换一个后端，(3) demo 的回放模式和"零 API 重复运行"用查表后端实现。

**共享接口（各子项目的契约）**

| 接口 | 职责 | 定义于 |
|---|---|---|
| `Kernel` | `async evaluate(KernelRequest) -> KernelResponse`；请求 = state（JSON）+ 若干类型化问题；响应 = 每个问题的概率分布 + 用量 | SP1 |
| `CacheStore` | 内容寻址的响应缓存；可导出为可分发的归档 | SP1 |
| `Ledger` | 每次运行的调用数、缓存命中、token、美元、延迟 | SP1 |
| `Persona` | 类型化的人设记录 + `render()`（输出给 state 的紧凑 JSON，数字一律转词语） | SP1（最小版），SP2 扩展潜在特质 |
| `Scenario` | 状态构建器 + 问题集 + 环境规则 + 指标 | SP3 |
| 运行目录约定 | `results/<时间戳>-<slug>/{config.yaml, ledger.json, metrics.json, predictions.jsonl, failures.jsonl}` | SP1 |

**核的提问契约（所有子项目统一遵守，源自 Jev 官方的弱点清单）**

1. 第三人称、预测式问法（"这位受访者选了哪个选项"），不用角色扮演式；最终采用哪种问法由 SP1 在开发集上比较后冻结。
2. 进 state 的数字一律在代码里转成词语桶（"很多转发"而不是 "1,243"）；算术、计数、日期比较全部留在代码里。
3. state 只放与问题相关的字段；字段顺序固定。
4. 同一类判断只用一种问法（Noul 与 Choice 的数值不可互比，阈值不可迁移）。
5. 选项用选项原文作 key，不用 A/B/C 字母标签。
6. 固定模型版本号（`jev-1.13.0`），不用 `jev-latest` 别名。

## 6. Demo 概要（细节留给 SP4 的设计）

现在就定下的决定：

- **回放优先**：先做能播放预计算运行的静态站点，再加实时模式。投稿、分享、现场演示都不依赖 API 可用性。
- **即时反应面板**用带权重的原型人群（≤1,000 个原型），对概率直接求加权平均（无采样噪声）。是否把多个原型打包进一个请求，取决于 SP1 的打包扰动探针结果。
- **并排传播**：对照组与干预组共用同一串随机数（CRN），观众看到的差异就是干预造成的差异。
- **成本计数器**始终可见（本次模拟的美元与耗时）。
- **"已验证 / 探索性"标记**：内容落在论文验证过的领域（美国政治新闻标题）之外时标为探索性。
- 不提供"优化这条消息"的按钮（见 §10）。

## 7. 成本与限流预算

- Jev：输入 $0.042 / 百万 token，输出免费；限流 1,200 RPM、250k token/s（官方称会动态调整）。
- SP1：OpinionQA 全量约 9 万次请求；SocSci210 每行一个请求，主运行每个单元取 200 名参与者（十余万次请求）。合计预计 < $20；受 RPM 限制，单个主运行需数小时。
- SP3：成本取决于状态设计。缓存友好（马尔可夫、粗粒度桶）时 ∝ 唯一的（persona × 内容 × 情境）组合数：2,000 人 × 20 条 × 8 情境 ≈ 32 万次 ≈ $8，之后的重复、各组、参数扫描几乎免费。带自由演化记忆时缓存失效：约 $0.84 / 次，4 组 × 200 次 ≈ $670。**设计上优先缓存友好的状态。**
- LLM 基线：只在固定子样本上跑；每次运行有硬性美元上限（超限即中止，可断点续跑）。LLM 价格在运行时从官方价格页写入 `configs/prices.yaml`，不凭记忆硬编码。
- 所有评估运行可断点续跑、幂等（缓存 + 增量写结果）。

## 9. 风险与对策

## 10. 伦理与使用边界

- 模拟结果不得作为真实民意或民调发布；论文与 demo 都写明验证范围与局限。
- 同一工具可被用来优化操纵性信息。对策：demo 不做说服力搜索；默认示例全部是减少危害的干预（事实核查标签、accuracy prompt、摩擦）；论文设伦理章节讨论双重用途。
- 只使用公开、去标识的调查 / 实验数据；遵守各数据集条款，不再分发受限数据。
- 误信息标题仅作为研究刺激材料使用，来源为已发表研究的公开材料。
